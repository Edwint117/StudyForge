# StudyForge M0–M11 task breakdown

Status: **proposed; awaiting first-session plan approval**. Prepared 2026-09-27 from docs/spec/00–10 and the complete engineering checklist. No application code or milestone gate is complete.

## Execution contract

There are **145 implementation/planning slices**, each budgeted at roughly **half a focused engineering day (3–5 hours)**, plus one gate pass per milestone. These are estimates, not a delivery promise: split a task further when the first testable behavior exceeds that budget; never trim its acceptance scope. Live provisioning, long-running evals and human reviews add elapsed time. Work strictly M0 → M11. Within a milestone, dependencies follow table order unless a row explicitly establishes a reusable foundation.

Every feature slice includes its migration where needed, user_id/RLS/pgTAP, strict boundary schemas, core service, API, localized accessible UI and appropriate unit/integration/E2E evidence. Cross-cutting controls remain obligations on every subsequent slice. A task row links to PRD story IDs and checklist notes; its described acceptance scope identifies the items it contributes toward. [The triage](checklist-triage.md) is the complete note/item ownership index, including closure milestones and item-specific overrides. A link is planned work, **not proof of completion**.

Before application code, the owner must approve this file and the triage per [kickoff first-session step 5](../spec/00%20-%20Agent%20Kickoff%20Prompt.md). After approval, execute M0-01–04 as the Second Step: finalize templates/schema/setup, merge .env.keys safely and check local/production connectivity. Never print or copy credentials into documentation. Ask once for missing key names only, using .env.keys names; keep working on independent tasks.

Use local branch m0-foundation, then m1-identity-security, m2-saas-shell, m3-mock-billing, m4-ingestion, m5-planner, m6-comprehension, m7-retention, m8-diagnostics, m9-exam-day, m10-data-operations and m11-hardening. No hosted remote. Commit each green slice with Conventional Commits. Update checklist evidence as it passes; never complete a whole note because one foundation passes.

## Gate protocol and dependencies

For **every** milestone, all individual gates in [doc 08](../spec/08%20-%20Milestones%20%26%20Acceptance%20Gates.md) remain mandatory in addition to task acceptance. Run pnpm verify (and the required full eval/load suite), save the report, self-review security-sensitive changes, prepare the human milestone summary, complete the scripted production rehearsal/deploy/smoke and required rollback verification, then tag only when all gate evidence exists. Resolve the merge/deploy ordering conflict below in M0 before implementing this workflow. Do not start M(n+1) while a prior gate is blocked. Failures generate follow-up slices, not waived gates.

Only a dedicated, cleaned-up smoke user touches production during tests; load tests use the local production-representative stack. No billing charge, public web hosting, real email provider or backup service is introduced by this plan.

Foundations intentionally arrive before their complete feature: M0 jobs already need RLS; M1 legal acceptance needs seeded versions; M2 pricing needs the minimal plan catalogue, while M3 builds billing; M2 course/sample onboarding completes ingestion in M4 and planning in M5; M4 past-exam extraction needs question/rubric storage before the M8 editor; M6 attempt-lock contracts gain real attempt state in M8; M6 Feynman evidence feeds M8 mastery. These are prerequisites within doc 08, not permission to skip gates or claim later modules complete.
